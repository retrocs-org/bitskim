# Transfer folders, progress and network checks (0.1)

The clients remember separate last-used send and receive folders. File selection starts in the last send folder; incoming save dialogs start in the last receive folder, falling back to the configured default when it no longer exists. Directory acceptance remembers the selected destination once for the whole transfer. Completed files remain at that destination. Automatic reception still follows the client's configured approval policy.

Folder history is small bounded local state: two checksummed records per direction. It is separate from transferable data and does not change the wire protocol. Windows, Atari and DOS use BSFOLD.DAT beside their settings; Amiga uses ENVARC:BitSkim/BSFOLD.DAT; macOS uses Application Support/BitSkim/folders.dat; RISC OS uses !BitSkim.Folders. A missing or corrupt record falls back to the configured folder. History contains local directory paths, never file contents.

Progress shows the current filename, position in the directory, overall transferred/total payload bytes and current speed. Folder entries may appear separately while a directory is created. The existing progress bar restarts for each file. Completion reports retain completed, skipped, failed and cancelled counts. Overall payload progress excludes directory metadata and does not imply delivery until the receiver confirms completion.

Cancel discards the remaining directory entries on both ends. The current partial file is removed, including a resumable partial on explicit cancellation; previously completed files remain. An unexpected interruption may retain a resumable partial on capable clients. A peer using an older release may retain its own pending entries after cancellation.

Open Tools (Transfer tools on some clients) for Network status. It reports stack, bind/local connection address, TCP and discovery ports, peer count, negotiated capabilities and recent errors. Test connection accepts an IPv4 address and optional :port (Windows/macOS; other clients use the selected, entered or most recent peer). It opens and closes a nonblocking TCP connection with a six-second deadline and sends no file. Success confirms TCP reachability only: discovery broadcasts, encryption and permissions are validated by ordinary transfers. Before any connection the local address may be unavailable; check the operating system's network settings.

Validation: host socket tests cover folder persistence, missing-folder fallback, reachability without an offer, and cancellation from either end. Native builds are generated for macOS arm64, Windows x64/x86, Amiga, DOS, Atari STiNG/MiNTNet/68060 and RISC OS ARM2/StrongARM. These changes have not yet been exercised in each native GUI or on physical retro hardware.
